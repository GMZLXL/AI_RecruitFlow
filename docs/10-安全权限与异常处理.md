# 10｜安全、权限、合规与异常处理

## 1. 安全边界

- `frontend` 对任何 API Key、Token、个人简历原文都无直接访问权限。
- `backend` 存储连接凭证，提供受限服务端代理；`live` 模式需要经过用户身份认证和角色权限控制。
- 不从普通企业微信群机器人采集全量聊天；真实群聊收集需企业授权、告知与合法合规审查。
- 应聘相关数据可能包含高度敏感个人信息，应按最小必要原则收集并设置数据生命周期。

## 2. 权限规则

| 能力 | HR | MANAGER | ADMIN |
|---|---|---|---|
| 查看本人负责申请 | 是 | 授权范围 | 是/审计授权 |
| 创建/修改本人负责申请 | 是 | 需授权 | 是（留痕） |
| 查看汇总看板 | 范围内 | 负责部门 | 全局（按批准） |
| 查看候选人联系方式 | 仅授权范围 | 默认掩码 | 需单独授权 |
| 审核 AI 变更 | 自己负责 | 管辖范围 | 是 |
| 配置密钥/字段映射 | 否 | 否 | 是 |
| 重试同步失败任务 | 否 | 否 | 是 |

## 3. 身份认证

- Mock 本地开发允许 `DEV_USER` 模拟身份，但只允许 `APP_ENV=development` + `APP_MODE=mock`，且必须在 UI 明显标示“开发模拟身份”。
- 生产采用企业微信 OAuth/企业身份系统，验证会话签名、过期时间、CSRF/CORS 策略及角色授权；开发者不得使用 `X-User-Role: ADMIN` 直接控制生产权限。

## 4. 敏感信息管理

- 联系方式使用加密字段或集中安全存储；展示时可按角色仅显示部分数字。
- prompt 脱敏：优先提供申请编号和阶段信息，不发送身份证号、家庭住址、简历全文。
- 审计信息不存全文聊天消息；仅按业务需要存安全摘要和引用。
- 数据过期后应支持删除/匿名化；操作留痕期限由企业合规政策决定。
- 日志中替换 Token、Authorization Header、手机号、邮箱等敏感字段。

## 5. 提示词注入与错误操作

- 用户消息永远视为不可信输入；包含“忽略规则”“输出密钥”等指令只参与文本解析。
- 输出 Pydantic JSON Schema 校验；只使用允许的业务操作枚举。
- 新增或修改前确认 `actor` 对目标 application 的权限。
- 多重匹配禁止自动提交；终态逆转、Offer 接受/拒绝等高影响操作须确认。
- AI 不直接执行 SQL、MCP tools 或外部 URL，全部经过明确白名单的服务方法。

## 6. 错误分类与恢复

| 错误 | 处理 |
|---|---|
| AI JSON非法/空内容 | 有限重试一次，然后提交人工审核 |
| 申请编号不存在 | 不自动新建同名申请，提示选择或新建 |
| 记录版本冲突 | HTTP 409，刷新后重新确认 |
| 外部同步500/超时 | outbox 指数退避重试，保留业务成功记录 |
| 外部同步401/403 | 标记 BLOCKED，等待管理员授权而非无限重试 |
| 消息重复 | 按 source+external_event_id 幂等返回原结果 |
| 企微验签失败 | 4xx 丢弃并安全记录，不解密/解析业务数据 |
| 任务超过最大重试 | 转 dead-letter，管理员人工处理 |

## 7. 验收安全测试

- 普通用户无法访问 `/sync/jobs` 或修改其他 HR 申请；429 限流生效。
- 前端 URL 手动改为他人 application_id 后返回 403/404。
- 未授权回调不能创建候选人；回调重复三次只处理一次。
- 前端源码和网络请求不含 Key；`.env` 在 `.gitignore`。
- 业务成功但腾讯文档失败，UI 显示待同步/同步失败，不显示远端成功。
