# 09｜开发、部署和运行手册

## S3 运行增量

API默认单进程，在lifespan内每2秒扫描最多50个outbox；数据库120秒租约及任务token控制领取恢复，网络调用超时20秒。无需新增Redis/Celery。`SYNC_WORKER_ENABLED=false`停用后台；默认SMARTSHEET_PROVIDER=mock。仅本地测试可设置MOCK_SHEET_FAILURE=timeout/after_write_timeout/permission，正常运行为none。

S2库先停服务并备份，运行npm run db:upgrade到0003_s3后再启动。Mock模拟表和既有remote_id同库不同事务持久化；备份数据库时包含它们。仅部署单实例API；租约是误启动保护，不作为生产多节点部署认证。

故障复现npm run smoke:sync-failure必须先停止API；创建虚构申请、在当前最多50项批次注入模拟权限失败。启动API（默认故障none），同步中心筛选dead填写原因重试；本轮次数重置，累计不清零。若任务已有更新版本则superseded，不能强行回退。

## 1. 环境要求

- Windows 11 / Linux / macOS；Git；Python 3.11+（本次验证3.12）；Node.js 22.12+；npm 10+；Docker Desktop/Engine（部署可选）。
- 开发期 SQLite，无需外部数据库；生产部署建议 PostgreSQL 与自动备份。
- 所有真实密钥只写 `backend/.env` 或部署环境，不上传版本库。

## 2. 本地启动

```bash
# 后端：进入 backend
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
pip install --require-hashes -r requirements.lock
cp .env.example .env
alembic upgrade head
uvicorn app.main:app --host 127.0.0.1 --port 8000

# 前端：另开终端，进入仓库根目录
npm ci
npm run dev:web
```

检查：`http://127.0.0.1:8000/api/v1/health` 与 `http://localhost:5173/`。`starter` 是 Mock 起点；完整功能待 Codex 根据文档逐项实现。

已有后端`.venv`时，可在根目录直接`npm run dev:api`，脚本自动选择Windows/Unix虚拟环境。该默认启动为单进程，不启用热重载。根目录`npm run check`统一执行契约、lint、Python/TypeScript检查、pytest和build；服务启动后`npm run smoke:http`验证真实HTTP链路并留下虚构演示记录。浏览器可视验收独立记录，不能用HTTP检查代替。

## 4. 数据库迁移

S1已引入Alembic，启动拒绝未迁移数据库；空库运行以下命令。旧S0库必须停止后端并通过-m scripts.migrations.upgrade_s0复制升级，保留原库和备份，再修改.env的DATABASE_URL指向新库；详见根README。不能直接stamp旧库。

```bash
alembic upgrade head
alembic revision --autogenerate -m '...'
alembic check
```

所有结构变更必须附迁移文件，并验证 SQLite 与 Postgres 兼容性。绝不以生产环境 `drop_all()` 重建数据库。

## 5. Docker Compose 目标

- `api`：FastAPI + Uvicorn，绑定内部 8000 端口；`web`：构建 React 静态资源，Nginx 代理 `/api`。
- `db`：可选 Postgres 服务，数据卷持久化；数据库密码由 env 或 secret 注入。
- 任务调度初期由单一 `worker` 进程运行；多副本 api 不启动重复 scheduler。
- 对外 HTTPS，反向代理超时/负载限制，日志不记录敏感正文。

## 6. 部署验收顺序

1. 构建前端 `npm run build`，后端 `pytest -q`，静态检查通过。
2. 运行数据库迁移；设置管理员身份/登录机制；初始化最小演示数据。
3. 运行 Mock 模式 E2E；再逐个切换 `hybrid` 和 `live`。
4. 检查 `/ready`，同步任务重试，备份恢复演练。
5. 开启外部流量前，完成企业微信回调验签和 Token 权限核查。

## 7. 监控与备份

- 监测：API 5xx、解析失败率、待确认积压、outbox失败队列、同步延迟、定时任务最后成功时间。
- 日志统一有 request_id/event_id；敏感字段脱敏；模型请求不得记录完整个人简历。
- 开发 SQLite 备份文件需确保一致性，生产 PostgreSQL 使用定期数据库备份并至少演练一次恢复。
- 业务表更新与 outbox 使用同事务提交；外部同步可重试且幂等。

## 8. 故障恢复手册

| 症状 | 优先排查 | 操作 |
|---|---|---|
| DeepSeek 超时 | 网络、余额、模型名、限制 | 降级为待确认或人工表单，不丢消息 |
| 腾讯文档401/400006 | Token、授权账户 | 标记认证失败，检查权限后重试 |
| 腾讯文档400007 | VIP/会员权限 | 呈现需升级，允许 Mock 或停止远端同步 |
| 企业微信回调失败 | 证书、URL、Token/AES、签名 | 使用官方回调验证工具，检查无敏感日志 |
| 报表数量不符 | distinct candidate vs application 口径 | 对照数据库事件表重算 |
| 重复数据 | external_event_id 与 outbox record 映射 | 回滚/人工清理重复并修复幂等测试 |
