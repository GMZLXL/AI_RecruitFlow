# 08｜腾讯文档与企业微信接入手册

## S3 当前实际状态

已实现SmartSheetAdapter协议、持久Mock、异步处理、指数退避/死信与管理员重试。腾讯适配器只返回blocked_by_credentials或blocked_by_schema，尚无经过真实Schema验证的查询/写入参数。当前无Token，运行`npm run integrations:tencent:discover`实测BLOCKED_BY_CREDENTIALS、退出2；没有向外部测试表写入。

只读发现器支持Streamable HTTP JSON/SSE响应：initialize→notifications/initialized→分页tools/list，限制响应大小、超时和页数，仅允许官方HTTPS端点，不跟随重定向。不实现tools/call，不接收任意URL/工具参数。实际Schema仅保存忽略的`.tools/tencent-mcp-tools.json`，不包含Authorization；发现成功仍不代表业务读写已验证。

后续提供服务端Token、独立测试文件/工作表授权后，先取得真实Schema，再实现字段映射和返回结构的契约测试，依次完成list_tables→list_records→add_records→update_records→list_records。不得拿通用MCP传输测试中的synthetic.example工具当作腾讯实测Schema；不得臆造字段ID。

当前依据：[腾讯文档官方指南](https://developer.cloud.tencent.com/mcp/server/11803)明确实际工具以tools/list为准；[MCP工具协议](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)、[传输协议](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)、[初始化生命周期](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle)用于只读发现器。腾讯授权、会员条件及实际传输兼容仍需实测，通用协议测试不能替代授权联调。

## 1. 真实接入前的核验清单

- 公司管理员批准创建企业微信自建应用并分配访问范围。
- 应用拥有接收消息与发送应用通知的相应权限和有效回调 URL。
- 已获得腾讯文档账号的合适授权，并拥有目标智能表格的读取/写入权限。
- 已完成候选人个人信息处理告知、数据最小化和安全审批。
- 真实凭证由企业管理员在部署时提供，不应写进交付包、GitHub 或 Prompt。

## 2. 腾讯文档 MCP（推荐路径）

官方文档：https://developer.cloud.tencent.com/mcp/server/11803
授权入口：https://docs.qq.com/open/auth/mcp.html
MCP 地址：`https://docs.qq.com/openapi/mcp`
鉴权 Header：`Authorization: <TENCENT_DOCS_TOKEN>`。

### 2.1 集成步骤

1. 由授权用户登录腾讯文档并获取 Token；放在后端环境变量中。
2. 先以独立 MCP 客户端连接，执行 `tools/list`，记录实际可用的 smartsheet 工具名、JSON Schema、必需参数和返回字段。
3. 选一张不含真实个人信息的测试表，使用 `smartsheet.list_tables` 获取 sheet_id，再使用 `smartsheet.list_records` 验证读权限。
4. 在测试表新增一条测试记录，读取返回 record_id，再用 `smartsheet.update_records` 修改它，最后查询验证。
5. 创建 `TencentDocsMcpAdapter`，将本地 application 字段映射为实际 field_id/value 格式。
6. 对外只暴露应用内部 `SmartSheetAdapter` 协议；不要让业务层直接拼 MCP 参数。
7. 对 400006 认证失败、400007 会员权限不足及工具不存在等情况给出具体提示，不能静默降级到成功。

### 2.2 注意

- 个人 MCP Token 是否适合企业长期服务端自动运行，需额外确认授权主体、有效期、续期与使用条款。
- 若企业账号不允许这种接入，需要重新评估官方企业 API / 合作连接器；不能绕过授权、抓取网页或调用未公开内部接口。
- 腾讯文档是否已经具有现成的企业级实时双向事件，需要专项核实；一期只承诺后端主动投影写入。

### 2.3 Mock 与 Live 适配器契约

```python
from typing import Protocol
class SmartSheetAdapter(Protocol):
    async def health_check(self) -> dict: ...
    async def upsert_application(self, application: dict, remote_record_id: str | None) -> str: ...
    async def list_remote_records(self, limit: int = 100) -> list[dict]: ...
```

Mock 适配器实现相同方法，但返回 `mode=mock` 并写入单独的模拟存储，不应在界面显示“腾讯文档真实同步成功”。

## 3. 企业微信自建应用

参考：https://wdk-docs.github.io/wework-docs/server/dev-guide/callback-setting/

### 3.1 管理员配置

- 创建自建应用，获取 CorpID、AgentID、应用 Secret（存于服务端环境）。
- 配置可访问的 HTTPS 消息回调 URL，如 `/api/v1/webhooks/wecom`。
- 配置 Token、EncodingAESKey，不混淆前者与腾讯文档 Token。
- 设置应用可见范围、接收消息、发送通知所需权限；完成域名/IP 等要求。

### 3.2 回调安全链路

- GET 校验 msg_signature 解密 echostr 并返回正确明文；不是直接回显密文。
- POST 根据签名和 AES key 解密消息，再校验 receiveId 和消息结构。
- 检查 timestamp、nonce、MessageId 防重放与重复事件。
- 将消息写入 ingestion_job 后立即按平台要求响应，工作流异步处理。
- 失败请返回真实错误/日志，不能对未验签流量返回“处理成功”。

### 3.3 群机器人能力边界

普通企业微信群机器人只适合作为主动发送招聘提醒的可选出口。第一期所有群消息需 HR 主动转发至应用或通过表单提交。未经会话内容存档授权，不能设计成“机器人自动读取任意群聊”。

## 4. DeepSeek API

官方：https://api-docs.deepseek.com/zh-cn/guides/json_mode/
- 环境变量 `DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL`、`DEEPSEEK_BASE_URL=https://api.deepseek.com`。
- 通过 OpenAI 兼容 SDK 访问；选择官方实际支持的模型，文档示例当前包括 `deepseek-flash`。
- JSON Output 需要 `response_format={"type":"json_object"}`，提示词必须明确要求 JSON 并给示例；空文本/截断要兜底。
- 模型只有“建议”权限，不应直接拥有数据库凭证或工具写入权限。

## 5. 联调验收脚本（人工执行）

1. 本地 Mock：输入一条消息 -> 创建候选人/申请 -> React可见 -> outbox变更为 mock synced。
2. 腾讯文档测试：授权 -> 动态 tools/list -> 新增/查询/更新一条脱敏记录 -> 检查 remote_record_id 映射。
3. 企业微信测试：验证 URL -> 发消息给应用 -> 后端收到 -> 验签解密 -> 返回 ACK -> 后台完成解析 -> 企微收到通知。
4. 撤销 Token：服务显示 authentication error，已经入库数据不丢；恢复 Token 后重试成功。
5. 防重复：同一个企微 MessageId 推送 3 次仅生成一次业务事件。
