# 11｜测试计划、样本集与上线验收

## 1. 质量门槛

每阶段 Codex 必须展示本地执行结果（无法运行要说明原因），不允许仅提交代码并口头宣称通过。

- `python -m pytest -q`：后端单元 + 集成测试。
- `python -m compileall app`：Python 语法检查。
- `npm run typecheck`：TS 编译检查。
- `npm run build`：前端构建检查。
- `npm run test`：Vitest 组件/服务测试（完整实现后）。
- `docker compose config`：部署配置有效性（完整实现后）。

S0新增根目录`npm run check`聚合已实现检查；`npm run contracts:check`比较运行时OpenAPI与已生成的TypeScript；`npm run smoke:http`需要5173/8000服务启动，仅验证HTTP/代理/Mock业务链路，不能代替浏览器布局与交互验收。S0未提供空的前端test成功脚本，组件测试在S4实现。
- Playwright E2E 可作为 P1；至少需要提供可复现的 API E2E 脚本。

## 3. DeepSeek 评测集

- 至少60条脱敏/合成消息：新增、状态更新、预约、候选人冲突、模糊时间、前后冲突、口语缩略词、恶意指令。
- 至少双人标注字段真值（或复核样本），字段级 micro accuracy 和关键业务错误率分开计算。
- 不应以少量演示样本达到100%为依据宣称已达到95%。
- 单独统计 `needs_confirmation` 覆盖率、误自动执行率。优先优化安全性而非尽可能低的人工确认率。

## 4. 端到端验收场景

1. 完全离线/无密钥 Mock：启动前后端，新增申请 -> AI解析 -> 列表更新 -> Dashboard展示 -> 模拟同步成功。
2. 自动写入：新增 -> 本地数据 `version=1` -> outbox 创建 -> MCP Mock返回 remote id -> map保存。
3. 更新：更新申请 -> `version=2` -> MCP Mock以 remote id 修改同一条记录。
4. 异常：删掉远端映射 -> 系统检测并提示，不造成重复新建。
5. 授权环境：在独立测试智能表格验证查询、新增与更新；文档 Token 不出现在日志。
6. 企业微信：验证 GET + POST 签名和 AES + 去重，模拟发送通知。

## 5. 验收交付物

- 源代码仓库、依赖锁文件 package-lock.json、requirements（建议固定版本）、数据库迁移。
- `.env.example`、Dockerfile/compose、README、故障排查清单。
- OpenAPI 接口文档、ER/状态图、角色与权限矩阵、测试报告。
- 外部接入有效/未有效状态截图；腾讯文档真实写入验证记录（若授权可用）。
- 演示视频或操作步骤：2分钟介绍、3分钟主链路、1分钟异常处理（可选）。

## 6. 项目完成定义（Definition of Done）

只有在“功能通过 + 自动测试通过 + 无明文密钥 + 错误可恢复 + 数据不越权 + Mock演示完整 + README可复现”的条件全部满足后，才允许把 MVP 标为完成。未获授权的腾讯文档/企业微信真实接入应标记 `blocked_by_credentials`，而不是“完成”。
