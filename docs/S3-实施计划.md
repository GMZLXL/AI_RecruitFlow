# S3 实施计划

本阶段仅实现异步外部投影，不扩展 S4 页面或 S5 企业微信。

## 影响文件和实施顺序

1. schemas/integration.py 先定义投影、任务读取、重试、统计与派发契约，再生成 OpenAPI/TypeScript。
2. db/models.py 与 0003_s3 增加任务修订号、领取租约、完成时间、provider、周期尝试；增加独立 Mock 远端存储与单实例处理锁。
3. integrations/smartsheet/ 定义协议、持久 Mock、凭证/Schema 未验证的腾讯适配器；只读 tools/list 发现脚本不臆造业务工具参数。
4. services/sync.py、jobs/ 同步处理器负责领取提交→事务外适配器→独立结果事务；指数退避、死信、重启恢复、版本防回退、管理员幂等重试。
5. api/v1/sync.py 和 React SyncCenter 支持异步唤醒、状态筛选、统计、失败原因、下次重试和人工重试。
6. README、docs/04/05/08/09/13/14、环境示例、实施报告与测试同步更新。

## 数据和兼容策略

数据库是事实源；每个实体版本仍只创建一个 outbox。只有 applications 投影到智能表格，其它事件明确标为 internal_only。旧任务 provider 固定为 mock，不随环境变更迁移到真实系统。Mock 远端独立事务持久化，以本地申请 ID 唯一并按版本更新，模拟“远端成功但本地确认丢失”后的幂等恢复。旧 S1/S2 payload 在处理边界转换，新增 payload 带版本化投影。

POST /sync/run 从同步处理全部任务改为幂等接受唤醒请求；返回 accepted，不宣称任务已经成功。任务状态仍由 GET /sync/jobs 查询。管理员重试需 Idempotency-Key、If-Match（任务 revision）和原因；业务 version 与任务 revision 分开。

## 验收条件和测试

- 无 Key 新增→后台 Mock 同步→修改复用 remote_id，状态明确模拟。
- 失败不回滚已提交申请；退避未到不执行，达到上限 dead，可人工重试。
- 权限403、过期revision409、同幂等键复用/冲突、并发锁与过期领取恢复。
- 网络调用不持有业务数据库连接；错误仅保存允许错误码，不输出凭证/上游原文。
- 远端删除/映射丢失进入人工处理；恢复重放不重复创建，旧版本不覆盖新版本。
- 空库升级/降级/再升级、模型迁移漂移、PostgreSQL离线DDL、契约漂移。
- pytest、Python/TS类型、lint、build、HTTP冒烟；真实腾讯联调仅在凭证/测试表授权可用时执行，否则 blocked_by_credentials。
