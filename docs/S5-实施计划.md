# S5 实施计划（2026-11-12）

范围：自建应用主动投稿回调、持久异步接收、发送应用通知、可配置提醒与去重；不采集群聊，不实现S6生产身份和部署。

先定义schemas/wecom.py，再实现数据库与服务，生成OpenAPI/TS后接入现有设置界面。影响文件：backend/app/{schemas,db,integrations/wecom,services,jobs,api/v1}，main生命周期、0005_s5迁移、Python依赖锁；frontend的services与设置功能模块；API/数据字典/接入指南/运行手册、README与实施报告。

数据：接收任务保存脱敏待处理文本、哈希和内部actor；提醒复用reminders，新增通知队列及领取租约。消息源/外部ID、提醒唯一键与通知唯一键分别去重；provider创建时固定。业务变化继续原子audit/outbox；网络调用在事务外，处理结果按token/version确认。密钥只从服务端环境读取；真实sender与内部用户需显式映射，未知/停用/无写权限者拒绝。

回调使用wechatpy企业加解密SDK，不自行编造AES算法；严格XML/大小/时间窗口/nonce/receiveId/AgentID校验。GET返回解密echo，POST持久化后返回success，异步复用S2 ingestion。无凭证默认Mock，真实接收/发送分别显式启用；回调Token沿用WECOM_CALLBACK_TOKEN；无真实授权不得宣称已连接。

提醒：配置提前面试小时数、反馈超时小时数、停滞天数；按实际业务事实生成持久任务，发送前复核权限和事实。Mock仅模拟，无发送凭证时待配置；发送API成功仅表示平台接受，不表示用户已读。网络发送结果不明进入需核实状态，避免盲目重发。

验收：无Key模拟投稿→同一ingestion→业务/审核→模拟通知；官方SDK加密样例GET/POST、非法签名/receiver/agent/过期/重复回调；停用与越权、事务回滚、租约恢复、提醒/发送幂等、接口错误与不明结果；空库升降/重升和模型漂移。运行完整check、db:check、HTTP冒烟及必要设置界面检查。真实管理员URL校验和消息投递保留blocked_by_credentials。
