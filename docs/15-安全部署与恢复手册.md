# 15｜S6 安全部署与恢复手册

S7已在原生Windows与GitHub Windows/Linux runner执行完整Mock验收，并在Linux runner实际构建、启动Compose、验证健康/Nginx代理及Mock业务HTTP。真实企业登录/TLS、生产覆盖容器运行、PostgreSQL和外部连接器仍未验收；本机Windows没有Engine。下文S6历史限制由此补充，证据见[16号手册](16-S7验收与演示.md)。

## 1. 环境与AI设置

开发保持`APP_ENV=development / APP_MODE=mock / AUTH_MODE=dev`，只绑定本机。管理员在系统设置→AI接入配置保存Key、模型与解析方式。Key留空保留，勾选清除会禁用环境变量Key回退。页面配置优先于环境初值，模型名由管理员填写；不提供任意API地址，后端固定允许DeepSeek官方HTTPS端点。

默认Mock只保存配置，不发模型请求。启用真实AI须操作员在服务器设`APP_MODE=hybrid`，保留`AI_PROVIDER=mock`作为初值，重启后管理员才可在页面选择DeepSeek。成功保存标记`configured_not_verified`，并非已验证可用；正式使用前应在授权隔离样本中核对响应、费用与隐私。没有真实Key时继续Mock。环境方式仍支持`DEEPSEEK_API_KEY[_FILE] / DEEPSEEK_MODEL`，同一secret不能同时给值和文件。

后端用AES-GCM保存受管Key。开发自动生成`backend/.secrets/ai-master.key`，生产必须提供32字节base64的`APP_SECRET_KEY[_FILE]`。加密主密钥及CSRF密钥留在服务器或secret store，不放前端构建、Git、截图或日志。数据库备份另配受保护的主密钥备份；丢失/错误主密钥不会回退到另一把环境Key。恢复前先确认主密钥匹配，轮换主密钥前需要另行规划旧密文解密与重加密；当前不提供自动轮换。

## 2. 企业登录网关契约

S6实现受信网关签发的应用会话校验，未实现企业IdP、OAuth回调服务器或企微OAuth后台配置。部署者须在应用前接同源HTTPS登录网关：`/sso/login`与`/sso/logout`由网关处理，其余路径代理到web；API8000不得发布到公网，8080继续只绑定loopback。网关须保留正确Host、Cookie、Origin；API不信任任意X-Forwarded身份头。

网关应采用授权码流程、PKCE、state，以及OIDC适用时的nonce/ID Token验证，严格限制回调URI。企微OAuth只能在完成企业授权、code交换和成员身份核验后映射为稳定subject，不能信任浏览器提交的UserID。OAuth安全要求参考[RFC 9700](https://www.rfc-editor.org/rfc/rfc9700.html)及[OIDC授权码流程](https://openid.net/specs/openid-connect-core-1_0.html#CodeFlowAuth)。真实租户授权与网关实现仍待目标环境完成。

成功登录后由网关签发应用专用RS256 JWT，并设置：

```text
Set-Cookie: __Host-recruitflow_session=<JWT>; Secure; HttpOnly; SameSite=Lax; Path=/
# 不设置Domain；网关登出须清除同名Cookie并结束上游会话。
iss = 与SSO_ISSUER完全一致
aud = 与SSO_AUDIENCE完全一致的单字符串
sub = 稳定企业成员标识，1~150字符
iat / exp = 整数UTC秒，0 < exp-iat <= 3600
jti = 每次会话唯一，1~150字符
```

API固定RS256、钉住本机RSA>=2048位公钥，检查issuer/audience/时间/必填claim。不会使用JWT中的role或浏览器角色；授权来自DB中有效AuthIdentity与User。验证机制参考[PyJWT用法](https://pyjwt.readthedocs.io/en/latest/usage.html)。签名私钥只在网关，应用只持公钥。不直接使用企业通用access token或ID Token充当本应用会话。当前无逐jti撤销表；最长1小时有效期，紧急撤销成员映射可立即阻止所有现存会话访问，签名密钥轮换需协调网关与应用公钥。

生产写请求还需精确`Origin=APP_PUBLIC_URL`和`X-CSRF-Token`；前端从`GET /api/v1/me`取得与当前会话绑定的CSRF令牌，仅存内存。Cookie变更后刷新身份。生产拒绝`X-Dev-User / X-User-Role`，关闭开发用户目录与API文档入口。

## 3. 显式用户授权与撤销

操作员在已配置生产环境的API运行环境中执行，issuer与网关一致，subject来自已核实企业身份。不要使用下列示例标识授权真实成员。初次管理员同样通过操作员授权，不自动信任JWT角色。

```powershell
# 原生部署：仓库根运行，先导入正式环境变量；示例全部为占位值
npm run ops:user -- provision --issuer https://identity.example.test --subject employee-demo --name 示例员工 --department engineering --role HR --key provision-demo-01
# 撤销使用provision实际返回的identity_id与version；说明必填
npm run ops:user -- revoke --identity-id <实际ID> --version <实际版本> --reason "成员离职，撤销访问" --key revoke-demo-01
```

容器中等价执行`python -m scripts.admin.users ...`。可选role仅ADMIN/HR/MANAGER（区分大小写，S7已修正旧示例）；已有映射权限不同会409，不静默提权。CLI写入同事务审计和outbox，并有幂等键。撤销立刻使映射无效；当前没有公开网页角色修改入口。命令行包含成员标识，应限制终端历史和运维日志访问。

## 4. Compose

需要当前Docker Engine与Compose。默认配置只做本机Mock，不需要任何三方凭证：

```powershell
npm run deploy:config
docker compose up --build -d
docker compose ps
# 浏览器打开 http://127.0.0.1:8080
docker compose logs --tail 100 api
```

API非root10001、web非root101；只读根文件系统、tmpfs、drop capabilities、日志轮转，API就绪后web启动。API启动前校验环境并迁移到head，现有数据升级前仍须备份。data卷保存SQLite，local-secrets卷保存开发主密钥；不要使用`down -v`清除业务卷。固定私有子网只用于本机Mock的开发代理，冲突时需同时调整网络与允许段，不扩大到公网。

生产将`deploy/production.env.example`复制为不入Git的`deploy/production.env`，填实际HTTPS origin、issuer/audience和受保护secret文件路径。准备网关提供的公钥、强随机CSRF密钥与加密主密钥。可在受限服务器目录中用以下Python片段生成后两者，生成内容不输出终端；文件必须为新文件：

```python
import base64
import os
import secrets
from pathlib import Path

directory = Path("deploy/secrets")
directory.mkdir(mode=0o700, parents=True, exist_ok=True)
for name in ("app.key", "csrf.key"):
    descriptor = os.open(directory / name, os.O_WRONLY | os.O_CREAT | os.O_EXCL, 0o600)
    with os.fdopen(descriptor, "w", encoding="utf-8") as output:
        output.write(base64.b64encode(secrets.token_bytes(32)).decode())
```

```powershell
node scripts/deploy/compose.mjs -f compose.yaml -f compose.production.yaml --env-file deploy/production.env config --quiet
docker compose -f compose.yaml -f compose.production.yaml --env-file deploy/production.env up --build -d
```

Compose文件型secrets是挂载文件，源文件ACL必须允许容器UID10001读取，并禁止无关用户访问；不能假定Compose替你变更宿主文件所有者/权限。Windows需在目标宿主核对ACL及Docker文件共享。参考[Docker Compose secrets](https://docs.docker.com/compose/how-tos/use-secrets/)和[服务配置](https://docs.docker.com/reference/compose-file/services/)。生产示例默认hybrid且三个provider均Mock，可先验证认证再逐项授权启用；腾讯写入仍因未验证Schema失败关闭。完整`APP_MODE=live`当前明确拒绝，不可绕过。

TLS在外层网关终止，只允许HTTPS访问，限制登录频率与cookie/回调路径。web代理只发必要headers，限制64KiB与10秒body；日志不记录URL查询和正文。Nginx配置已按[header继承规则](https://nginx.org/en/docs/http/ngx_http_headers_module.html)保留安全header；运行时仍需在目标环境检查SPA、API、错误响应、TLS、SSO跳转与安全header。本机仅执行两份官方Compose `config --quiet`，未执行以上up命令。

## 5. 健康、限流与任务

- `GET /api/v1/health`：存活；`GET /api/v1/readyz`：数据库版本和已启用任务的领导租约，未就绪503。
- 管理员`GET /api/v1/ops/status`：schema、leader/standby、心跳、每类任务最近循环/成功/安全错误码、实际队列计数与最老未完成申请同步时间。不返回租约token。
- 默认每IP每分钟600请求，AI录入/模拟投稿每actor每分钟30；429含Retry-After。配置`REQUEST_RATE_PER_MINUTE / INGESTION_RATE_PER_MINUTE`。单进程内存限流最多10000键；外层网关仍应按真实客户端限流，不伪称多节点全局配额。
- 全局DB领导租约45秒，每5秒续租；只有leader启动同步与企微循环。另保留任务领取token，旧token不能提交新状态。进程异常后接任等待租约过期，监控应观察心跳与队列年龄；readiness只代表租约，不保证每个业务任务成功。
- 日志使用事件白名单JSON，不记录正文/完整URL/异常对象/Key。未知依赖消息被省略；排查结合request_id、受权业务历史和队列安全码。真实部署须核对外层网关、IdP、容器采集器也不记录token/正文。

支持单实例SQLite和一个API进程；不需要Redis/Kafka/Celery。异常同步在同步中心依版本、幂等键与说明重试；企微uncertain需人工核实，不自动重发。

## 6. SQLite备份与恢复

先确认服务实际`DATABASE_URL`，不要凭文件名猜测。根npm封装在backend工作目录运行，下列相对路径均据此解析。在线backup使用SQLite一致快照、quick_check、外键检查、各核心表计数、SHA256及manifest；恢复要求manifest匹配且目标为新文件，不覆盖当前库。

```powershell
npm run ops:backup -- --source recruitflow.db --destination ../.tools/backups/run-01.db
npm run ops:restore -- --source ../.tools/backups/run-01.db --destination ../.tools/backups/recovered-01.db
```

备份`.db`和同名`.manifest.json`，并在单独受限位置备份匹配的主密钥。文件含业务资料/密文，应加密备份介质、限制ACL、设保留期限及异地恢复演练。SHA256只能检测内容变化，不能证明来源可信；保护manifest与备份链。

恢复命令只生成待验证新库，清除协调租约，保留业务/通知状态及原有恢复语义。核对revision/计数/关键业务及主密钥后，停止原API与所有worker；将新库放在持久数据目录，修改`DATABASE_URL`指向它，先执行迁移检查，再启动一个API并验证readyz、ops与Mock业务。保留旧库和配置以便回滚，迁移前快照不能直接给旧代码运行，须匹配版本。不要同时让新旧实例写同一外部队列；真实通知结果不明继续人工核实，不因恢复盲目重发。

生产容器可在api内执行`python -m scripts.operations.backup ...`，路径用`/data/...`；将备份与manifest安全复制到卷外。主密钥单独归档。PostgreSQL需目标环境的数据库原生备份/恢复演练，本脚本只支持SQLite。

本机S6实际对运行中的数据库备份、恢复到新的非活动文件，通过revision `0006_s6`、41条申请与当时1044条审计一致性校验；没有替换当前库或触发外部通知。浏览器验收随后另有AI配置审计，计数自然会增加。
