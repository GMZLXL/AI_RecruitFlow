# 02｜PRD 产品需求规格说明书

## 1. 文档信息
产品：AI RecruitFlow；版本：MVP v0.1；用户：HR、招聘负责人、系统管理员；目标终端：PC 浏览器优先，响应式适配平板和手机。

## 2. 用户角色与权限

| 角色 | 可以做什么 | 不可以做什么 |
|---|---|---|
| HR | 自己负责的候选人/申请/面试管理、AI录入、待办、统计 | 查看无权业务、管理密钥 |
| 负责人 | 授权范围内进度查看、招聘看板、待办监督 | 修改系统集成密钥、获取未授权敏感字段 |
| 管理员 | 用户角色/岗位规则/字段映射/连接状态/审计 | 越过授权无依据地采集私人通讯内容 |

## 3. 用户故事与验收条件

### US-01 自然语言消息录入｜P0
作为 HR，我希望发送日常中文招聘消息后，系统自动识别字段并生成候选人记录或更新申请进度。
- 输入 1~2000 字；超过长度提示分段；前端显示识别中、完成、需确认、失败。
- 结果显示意图、候选人编号/姓名（脱敏视角色）、岗位、原状态和目标状态、下一步时间。
- 用户显式提交重复外部事件 ID，不能造成两次写入；相同文本但业务上不同时间发生的事件不应被错误去重。
- 模型提取不到业务对象或新状态时进入待确认队列，不写入正式业务表。

### US-02 候选人和多岗位申请｜P0
- candidate 可拥有多个 application，application_id 必须唯一。
- 候选人列表支持姓名、岗位、状态、负责人、渠道、时间筛选和分页。
- 详情展示当前申请状态、面试历史与审计日志。
- API 的字段级权限与前端显示权限一致；联系方式默认仅对授权人员开放。

### US-03 面试管理｜P0
- 支持初试、复试、加面等可配置轮次，状态可设待安排、已安排、已完成、已取消。
- 每次面试有开始时间、面试官、结果、反馈日期；通过后可以安排下一轮。
- 结果与下一轮安排要分开记录，不能将“初试通过”误写成“复试通过”。

### US-04 AI待确认队列｜P0
- 触发原因：申请不唯一、字段缺失、冲突状态、模糊时间、API校验失败。
- 展示原消息的必要片段、候选匹配选项、建议修正内容。
- 审核操作：确认执行 / 修改字段并执行 / 驳回；每次审核记录审核人和时间。
- 30 天以上未处理记录可归档，实际留存周期可配置。

### US-05 腾讯文档同步｜P0
- 应用内业务成功后生成 outbox 任务，具有 pending/syncing/synced/failed/dead 状态。
- 任务重试不重复创建文档记录；保存 local application_id ↔ remote record_id 映射。
- 同步页显示最近同步状态、最后成功时间、错误码、重试按钮。
- 未配置 Token 时展示“待配置”而不是虚假“同步成功”。

### US-06 招聘看板｜P0
- 指标卡：新增申请数、待面试数、待反馈数、发出 Offer 数、已接受数。
- 图表：阶段漏斗、岗位进度、每周新增趋势、待办分布。
- 筛选：日期范围、岗位、负责人；统一展示实际统计口径说明。
- 无数据状态不得生成虚假数字。

### US-07 自动待办提醒｜P1
- 允许配置面试提前 N 小时提醒、反馈超时 N 小时、停滞 N 天提醒。
- 定时任务按时区计算，并保存提醒唯一键防止重复消息。
- 无企业微信发送凭证时仅写入应用通知队列，不假称已发送。

### US-08 AI周报｜P1
- 后端先聚合统计，再发送脱敏指标与必要上下文给模型。
- 结构：本周概览、岗位风险、待办、建议；所有数值来自数据库。
- 失败时退回纯模板报告，避免空白结果。

### US-09 连接配置｜P0
- 显示 DeepSeek、企业微信、腾讯文档连接状态，但绝不明文回显 Token。
- 支持测试连接、字段映射预览、同步健康检查；不可持久化敏感密钥到浏览器 localStorage。

## 4. 页面信息架构

侧边导航：`工作台`、`候选人`、`招聘申请`、`AI录入与审核`、`面试与待办`、`招聘数据看板`、`同步中心`、`系统设置`。

## 5. 状态定义

- 申请阶段：applied、screening、interview_1、interview_2、offer、hired、rejected、withdrawn。
- 面试结果：pending、passed、failed、cancelled；面试轮次 independent，阶段可按组织配置。
- 事件状态：received、parsing、needs_confirmation、applied、rejected、failed。
- 同步状态：pending、processing、synced、failed、dead。

## 6. 非功能需求

- 分页 API 默认 20、最大 100；前端首屏加载目标 ≤3s（测试网络/数据量需注明）。
- 对所有业务写操作保存 actor、source、event_id、changed_fields、created_at。
- 秘钥保存在服务器环境变量/密钥服务；禁止打印明文简历或 API Key。
- 外部服务不可用时允许本地写入并提示同步待恢复，不能丢失业务事件。
- 按日期统计以企业业务时区（默认 Asia/Shanghai）为准，数据库统一使用 UTC 时间。
- 浏览器需要适应 1440/1024/390 px 的三类宽度，移动端优先保持查询和人工确认可用。

## 7. 版本优先级

- 必做 P0：认证基础、招聘业务 CRUD、AI解析、冲突审核、Outbox、看板、接口测试。
- 增强 P1：企微推送、提醒、周报、导入导出、规则配置。
- 待研究 P2：授权会话存档、双向同步、语音/图片解析、复杂招聘智能体。

## 8. 边界情形

1. 同一姓名多个申请：不得按姓名直接更新。
2. “明天下午”未给具体时间：不得猜测，提示补全。
3. 录用后又出现“初试通过”：拒绝直接逆转，须人工确认并记录理由。
4. 外部同步失败：本地记录保留、展示 sync_failed、后续重试。
5. 同一消息反复推送：external_event_id 或 MessageId 幂等。
6. 用户无权：后端返回 403，不能依赖前端隐藏按钮。
7. 数据量大：分页+数据库索引，不一次拉取全部个人数据。
