# S4 实施计划

## 范围与用户补充

保留浅色企业级Ant Design界面。实现Dashboard、Candidates、ApplicationDetail、AIInbox、Tasks、SyncCenter、Settings的实际业务交互、Loading/Empty/Error、筛选分页与1440/1024/390px响应式。用户明确要求同时增加Offer发出/接受/拒绝及已录用指标，并生成虚构姓名、岗位和面试演示数据。Offer接受不等于录用，拒绝Offer不自动淘汰。

## 先契约再实现

- schemas新增独立Offer、统计趋势/岗位进度、待办投影、详情历史及安全设置读取结构；由OpenAPI生成前端类型。
- 新迁移0004_s4只新增offers表，application_id唯一，sent/accepted/declined、独立version、UTC发出/反馈时间。旧申请不猜测Offer状态，接受率分母只含有明确反馈的记录。
- dashboard与tasks复用权限/筛选口径；日期按申请创建时间[from,to)，默认看板近30天；待办是面试/审核/同步/停滞事实投影，自动提醒发送留S5。
- 所有新增Offer写入继续要求后端权限、幂等、版本、状态机，并同事务记录审计/outbox；“登记发出”不实际发消息。

## 验收条件

1. 看板与列表筛选一致；数值来自SQLite；无数据不绘制假图；Offer接受/拒绝与录用分开。
2. 候选人/岗位选择支持一人多岗；列表→详情→人工阶段/面试/Offer记录→看板和待办可见。
3. AI歧义在Web完成审核；409保留输入并提示刷新；API失败有明确恢复路径。
4. HR本人、经理所属部门只读；设置敏感状态/同步中心管理员专用；后端拒绝越权和敏感字段泄露。
5. 虚构样本脚本使用固定演示标识、幂等重跑，不覆盖或清空现有数据，数据库文件继续忽略。
6. python pytest、TS/Python类型、lint、build、契约和迁移检查、前端组件/路由/错误状态测试通过；实际HTTP与1440/1024/390px浏览器验证。

真实DeepSeek/MCP/企微凭证继续阻塞；本阶段不进行生产认证、提醒推送或真实外部写入。
