# S1｜数据、迁移、身份与状态机实施计划

## 边界与文件

S0浏览器主链路已补验。S1只完成基础业务，不实现DeepSeek、正式MCP任务调度或完整AI审核产品。

- `app/db.py`：数据库连接、UTC类型、SQLite外键、十二类实体；ID使用UUID字符串。
- `app/schemas/`：请求/响应独立、引用式申请创建、开发身份、分页筛选、版本、状态/面试枚举、受控扩展字段。
- `app/security.py`：开发身份开关，服务端固定用户目录，HR本人/经理部门/管理员范围。
- `app/services.py`：事务、幂等、审计/outbox、条件更新、状态机、终态逆转确认记录。
- `app/main.py`及业务路由：岗位/候选人/申请/面试CRUD和查询、开发身份、保留Mock闭环。
- `alembic.ini`, `alembic/env.py`, `alembic/versions/`：空库迁移，S0旧库保留备份后离线升级。
- `tests/`：迁移、权限、状态、事务、并发版本、软删除与扩展契约测试。
- 前端API/开发身份切换、生成类型、HTTP冒烟；同步`contracts/openapi.yaml`、docs/04/05/13、README和实施报告。

## 设计决定

1. API继续snake_case/字符串ID/UTC；读投影保持application_code/candidate_name/position_title。引用candidate_id/position_id实现一人多申请，保留旧便捷输入为独立创建分支。
2. 用户目录由服务端在Mock开发模式种入虚构用户，前端仅提交用户ID、不提交角色。`DEV_AUTH_ENABLED`显式开关；生产不接受开发header，无生产登录实现时拒绝启动。
3. 候选人有owner_id；申请负责人必须与候选人归属兼容。经理只读所属部门，HR只读写本人，管理员管理全局。候选人列表不包含联系方式；S1不提供联系方式采集入口。
4. 更新/软删除必须If-Match与幂等键，数据库条件更新保证版本冲突409。所有业务变更同时写审计与版本化outbox；网络调用不在事务内。
5. 普通前向阶段白名单、异常结束需人工操作；终态逆转创建confirmation而不直接修改。S1保留待确认记录，完整审核解析/驳回闭环由S2实施。AI禁止自动录用/淘汰。
6. 扩展字段仅接受配置白名单（示例organization.referral_tag，标量值、限制大小）；不允许扩展字段覆盖owner/stage等核心权限字段。核心新增字段依旧需要迁移。
7. 空库通过Alembic建立实体；启动不再create_all。S0数据库先备份，再通过显式离线升级命令迁移UUID/岗位/历史/映射；拒绝静默删除、stamp或直接破坏原库。

## 验收

- 同一candidate在两个岗位申请，编号唯一；同名不自动合并。
- HR越权403、列表/统计/事件按范围过滤；经理只读，管理员可配置。
- If-Match不符409；重复幂等键不重复写、异体请求409；软删除后查不到且历史可追溯。
- 终态逆转返回needs_confirmation，实体版本不改变；无权者不能制造确认任务。
- UTC写读一致；SQLite外键生效；业务+审计+outbox同事务，失败全回滚。
- Alembic空库upgrade/check通过；S0迁移保留记录、历史/映射和备份；PostgreSQL只验证DDL可编译，不冒充真实服务测试。
- `npm run check`通过，前后端启动及HTTP Mock闭环通过。保存S1本地提交，不推送远程。
