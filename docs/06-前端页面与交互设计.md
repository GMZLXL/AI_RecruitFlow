# 06｜React 前端页面设计与交互规格

## S6 当前增量

系统设置新增管理员AI接入面板，沿用Ant Design纵向表单：解析方式、模型、密码Key、清除Key与变更说明。只显示Key配置状态/版本，不回显已存Key。空Key保留，清除同时禁用环境回退；保存成功清空Key并显示版本，失败保留草稿，刷新保留编辑供核对。Mock可保存Key但不能启用DeepSeek，真实调用需服务器hybrid门禁。HR/负责人无管理表单且后端403。

应用先auth/config再/me，只有开发认证加载模拟用户目录与选择器；SSO显示企业登录/退出入口，无开发身份回退。Axios仅dev发开发头，SSO写入从内存加CSRF。Key不存localStorage/sessionStorage。1440/1024/390px及虚构Key保存/清除已实测，手机无页面横向溢出；独立UI评审Ship。企业登录顶栏通过组件/源码检查，真实企业会话未联调。

## S5 设置扩展

沿用Ant Design与现有导航，在系统设置添加管理员企微面板：接收/发送分别显示配置状态；“接入与用户绑定”“提醒规则”“模拟投稿”三标签。指引只显示环境变量用途，不填写或回显密钥；外部UserID绑定须理由。提醒默认关闭，版本冲突保留输入；模拟投稿失败保留原消息ID/幂等键，新消息显式生成新ID。202显示已接收，后台结果需刷新或到AI录入查看。

设置（管理员）和面试与待办（本人）均有通知记录；明确模拟发送、平台接受、结果不明等文本状态，后者不提供重发按钮。管理员仅对明确失败/待配置通知填写依据后重试。宽表格内部横滚，表单单列；没有真实凭证时仍可演示投稿与模拟通知。S5界面验证见实施报告。

## 1. 视觉与布局规范

### S4 已实现与验证

七页实际运行，详情包含基础/面试/Offer/安全历史；所有请求来自统一Axios与生成类型。Dashboard日期/岗位/负责人/阶段、候选人姓名编号/渠道/岗位/负责人/阶段/日期与分页、待办类别/参考时间/岗位/负责人均连到数据库，非硬编码指标。

Offer增加实际发出/接受/拒绝表单、时点与登记依据，接受不自动录用；空数据接受率显示“暂无明确反馈”。AI审核按意图只显示必要字段，少见ID匹配放高级折叠；失败保留输入，409提示刷新，失败重试复用接入事件ID。

主导航1440/1024为左侧栏，390为显式“导航”按钮+Drawer；宽表格只在容器内部横向滚动，编辑抽屉不超过100vw。实际浏览器完成移动审核、Offer反馈和角色访问；负责人只读，越权不显示目标申请内容。见实施报告；“全部旧版本浏览器/所有辅助技术”不在本轮实测声明内。

图表按模块/路由延迟加载，保留文本口径和岗位摘要。新增PRODUCT.md/DESIGN.md记录已确认业务与现有Ant Design界面约定。下文保留原目标规格；自动提醒发送在S5，生产登录在S6。

- 面向 HR 工作效率：浅色、企业级、信息密度适中，不使用炫技特效。
- PC 使用左侧固定导航（220px）+ 顶栏 + 主内容区；小屏幕侧栏收起，表格使用横向滚动或卡片模式。
- 推荐 Ant Design 组件：Layout、Menu、Table、Form、Drawer、Modal、Tag、Alert、Result、DatePicker、Steps、Timeline、Tabs、Select、Statistic、Skeleton。
- 颜色：主色建议企业蓝 `#1677ff`，待确认橙，成功绿，失败红；颜色不应是状态的唯一辨识方式。
- 国际化先中文；日期/时间展示业务时区，支持操作反馈 toast+明确结果区。

## 3. 页面逐项定义

### P01 工作台 `/dashboard`
- 顶部筛选：日期（默认近30天）、岗位、负责人；点击查询使所有图表同步刷新。
- 5个指标卡：新增申请、待面试、待反馈、Offer发出、Offer接受。
- 图表：阶段漏斗（人数以申请维度）、岗位完成率条形图、每周新增折线图。
- 右侧或下方提醒区：即将面试、反馈超时、同步失败。
- 空态：无该条件数据；错误态：保留筛选条件并提供重试。

### P02 候选人列表 `/candidates`
- 搜索：姓名（按权限）、候选人编号、岗位、负责人、招聘阶段。
- 表格字段：申请编号、候选人、岗位、负责人、当前阶段、最近结果、下次面试、更新时间、同步状态、操作。
- 操作：查看详情、手动新增；所有编辑都通过后端授权。
- 点击行跳转申请详情；敏感字段按权限掩码。

### P03 招聘申请详情 `/applications/:id`
- 顶部候选人基本信息（脱敏）与当前阶段、申请编号。
- Tab1 基础信息；Tab2 面试时间线；Tab3 AI解析/审核记录；Tab4 状态与同步历史。
- “更新阶段”需填写原因并显示变更前后状态；有冲突则提示用户刷新。
- 面试安排 Drawer：日期时间、面试官、轮次、备注；不能安排过去时间（管理员可带理由例外录入历史）。

### P04 AI录入与审核 `/ai-inbox`
- 左侧文本框（多行，上限2000字）与“解析并处理”按钮。
- 右侧结果面板：解析中、自动完成、待确认、失败；字段表可编辑确认。
- 待确认列表：触发原因、原消息安全摘要、匹配候选人、确认/修改/拒绝。
- 每次处理展示 `ingestion_id` 和结果；外部同步状态不与业务写入状态混淆。

### P05 待办 `/tasks`
- 分类：今日面试、面试待反馈、招聘停滞、同步异常。
- 查询条件：负责人、到期时间、类型；标记已完成须审计。
- 各条待办可跳到目标申请；按 RBAC 过滤。

### P06 同步中心 `/sync`
- 统计：待同步、失败、死信、最近成功。
- 列表：任务编号、申请编号、目标系统、尝试次数、最近失败原因、下次重试时间。
- 支持管理员手动重试，不能向所有 HR 展示 Token 或原始敏感内容。
- `Mock` 状态显著标注“模拟同步，不是腾讯文档写入成功”。

### P07 系统设置 `/settings`
- 角色权限说明、岗位字典、阶段规则、提醒阈值、腾讯文档字段映射、连接健康状态。
- “测试连接”需要后端执行，不把 Secret 发给浏览器；无密钥时展示缺失配置项名称。

## 4. 主要交互状态

| 状态 | UI反馈 |
|---|---|
| loading | Skeleton/Spin，禁用重复提交按钮 |
| success_local | 保存到业务系统成功，腾讯文档显示“待同步” |
| success_remote | “同步成功”并记录时间 |
| pending_confirmation | 弹出确认抽屉，显示为什么不能自动执行 |
| validation_error | 具体字段错误，焦点定位到错误项 |
| permission_denied | 显示无权访问，不泄露记录存在与否 |
| integration_missing | 显示“未配置腾讯文档授权”并允许 Mock 演示 |
| sync_failed | 黄色/红色提示、可查看原因与重试（仅管理员） |

## 5. 组件规范

- `ApplicationStatusTag`：所有阶段唯一映射；`SyncStatusTag`：区分待同步/已同步/失败/模拟。
- `ApplicationTimeline`：事件按时间倒序展示，必要字段省略敏感信息。
- `AIResultPanel`：只读抽取结果 + 可控编辑确认；不得允许任意 JSON 直接执行。
- `AppErrorBoundary`：避免单图表错误造成白屏。
- `EmptyState`：带具体文案，引导创建第一条申请。

## 6. 可访问性与响应式

- 表单 `label` 清晰；按钮有文字，图标单独出现时配 `aria-label`。
- 关键状态提供文本标签；键盘可打开并操作抽屉；弹窗具备焦点管理。
- 390px 移动端仍能完成 AI 录入、确认、查看待办；宽表格用滚动而非挤压。

## 7. 前端路由保护

React 路由可按 role 控制界面，但不能代替后端授权。前端所有 API 调用统一在 `src/services/api.ts`，请求失败能区分 401、403、409、422、500。
